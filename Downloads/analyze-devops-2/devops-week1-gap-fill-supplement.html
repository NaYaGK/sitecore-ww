AWS Billing Safety — Do This Before Anything Else

Slot after: aws configure
Before: launching EC2

🔴 This is not optional

Beginners have received £500+ surprise AWS bills from forgotten EC2 instances, NAT Gateways, or accidentally created resources in the wrong region. Set a billing alarm on your very first day in the console — it takes 4 minutes and prevents a potentially traumatic experience.

⌨️ Set Billing Alarm + Budget via CLI

AWS Billing Safety Setup — Day 2, Session 1 Critical — Do First
Step 1: Enable billing alerts (one-time account setting)
# Must be done in the AWS Console (not CLI) — one time only: # Console → Account (top right) → Billing preferences # ✓ Check: "Receive Billing Alerts" # ✓ Check: "Receive Free Tier Usage Alerts" # Click Save. Takes effect immediately.
Step 2: Create a billing alarm via CLI (us-east-1 only — billing metrics are global but live there)
$aws sns create-topic --name billing-alerts --region us-east-1
{ "TopicArn": "arn:aws:sns:us-east-1:123456789:billing-alerts" } # Save the TopicArn — you'll need it below
$aws sns subscribe \
--topic-arn arn:aws:sns:us-east-1:YOUR_ACCOUNT:billing-alerts \
--protocol email \
--notification-endpoint your@email.com \
--region us-east-1
# Check your email — you must CONFIRM the subscription or alerts won't send
$aws cloudwatch put-metric-alarm \
--alarm-name "Monthly-Bill-10-USD" \
--alarm-description "Alert when estimated charges exceed $10" \
--metric-name EstimatedCharges \
--namespace AWS/Billing \
--statistic Maximum \
--dimensions Name=Currency,Value=USD \
--period 86400 \
--evaluation-periods 1 \
--threshold 10 \
--comparison-operator GreaterThanOrEqualToThreshold \
--alarm-actions arn:aws:sns:us-east-1:YOUR_ACCOUNT:billing-alerts \
--region us-east-1
# Alarm created. You will be emailed if your monthly bill approaches $10. # Change threshold to 1 (dollar) for extra safety during learning.
Step 3: Create a Budget (harder limit)
$cat > /tmp/budget.json << 'EOF'
{ "BudgetName": "DevOps-Learning-Budget", "BudgetLimit": { "Amount": "10", "Unit": "USD" }, "TimeUnit": "MONTHLY", "BudgetType": "COST" } EOF
$ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
$aws budgets create-budget \
--account-id $ACCOUNT_ID \
--budget file:///tmp/budget.json
# Budget set. AWS will alert at 80% and 100% of $10 monthly limit.
Step 4: aws configure with named profiles (safe multi-account)
$aws configure --profile learning
AWS Access Key ID: YOUR_IAM_KEY AWS Secret Access Key: YOUR_IAM_SECRET Default region: eu-west-1 Default output format: json
$aws s3 ls --profile learning # Use explicit profile flag
$export AWS_PROFILE=learning # Or set it as env var for the session
$aws sts get-caller-identity # Confirm correct profile is active
# Named profiles protect you from running commands in the wrong account # In future: "learning" profile vs "production" profile — you'll never mix them
Daily habit: stop unused resources before closing laptop
$aws ec2 describe-instances \
--query 'Reservations[*].Instances[*].[InstanceId,State.Name,Tags[?Key==`Name`].Value|[0]]' \
--output table
# See all instances and their state — run this before closing for the day
$aws ec2 stop-instances --instance-ids $(aws ec2 describe-instances \
--filters "Name=instance-state-name,Values=running" \
--query 'Reservations[*].Instances[*].InstanceId' \
--output text)
# CAREFUL: stops ALL running instances — review before running in real account

⚠ Free Tier Traps — Know These Before They Bite You

NAT Gateway: ~$0.045/hour + data transfer. Costs money from the first second. Always delete after experiments.

Elastic IP not attached: An Elastic IP with no instance attached costs $0.005/hour. Delete unused EIPs.

EC2 in wrong region: Free tier is per-account, not per-region. If you launch a t2.micro in eu-west-1 AND us-east-1, you exceed free tier hours.

RDS (Week 2): Even a stopped RDS instance still charges for storage. Snapshot + delete when not in use.

Git Branching, Stash, and Safe Undo

Slot after: first push to GitHub
Time: ~45 minutes

Why This Was Missing and Why It Matters

The Day 2 pack covered the single-branch git workflow (add → commit → push on main). That's fine for solo learning but every team uses branches. "Show me a git branching workflow" is a first-round interview question. You need to know it before your first application.

🌿

Why Branches Exist

A branch is an independent copy of the codebase. You do new work on a branch so main stays clean and deployable. When the work is ready, you merge. Main = always working. Branch = work in progress.

Production rule: never commit directly to main. Create a branch, do the work, merge via PR.

🗃

git stash — Park Your Work

You're mid-task and need to switch branches. Your changes aren't ready to commit. git stash saves them temporarily. git stash pop brings them back. Like a clipboard for code.

Used daily on teams. "I need to quickly check something on main — let me stash this first."

↩️

git revert vs git reset

git revert: creates a new commit that undoes a previous one. Safe — history is preserved. git reset --hard: moves HEAD backwards, erases commits. Destructive — never use on shared branches.

Rule: revert on shared branches. reset only on your private branch before first push.

⌨️ Git Branching Command Flow

Git Branching — The Full Workflow Day 2 Add-on
Create and switch to a new branch
$git branch # List all branches. * = current branch
* main
$git checkout -b feature/add-health-script
Switched to a new branch 'feature/add-health-script' # Naming convention: feature/description, fix/description, docs/description
$git branch
* feature/add-health-script main
Do work on the branch, commit it
$echo "# Health Check Script" > scripts/health_check.sh
$git add scripts/health_check.sh
$git commit -m "feat: Add health check script skeleton"
$git push -u origin feature/add-health-script
Branch 'feature/add-health-script' set up to track remote branch.
Switch back to main and merge
$git checkout main
$git pull # Always pull latest main before merging
$git merge feature/add-health-script
Updating a3f4b12..c8d9e01 Fast-forward scripts/health_check.sh | 1 +
$git push
$git branch -d feature/add-health-script # Delete merged branch locally
$git push origin --delete feature/add-health-script # Delete from GitHub too
git stash — save unfinished work temporarily
$echo "work in progress" >> README.md
$git stash
Saved working directory and index state WIP on main: c8d9e01
$git status
nothing to commit, working tree clean # Changes are hidden. Safe to switch branches or pull.
$git stash list
stash@{0}: WIP on main: c8d9e01 feat: Add health check script skeleton
$git stash pop
On branch main — Changes restored.
git diff — review changes before committing
$git diff # Changes not yet staged (unstaged vs last commit)
$git diff --staged # Changes staged but not yet committed
# Run git diff --staged BEFORE every commit. Review what you're about to save. # This is how you catch accidentally staged files (like .env or secrets)
git revert — safe undo on shared branches
$git log --oneline
c8d9e01 (HEAD) feat: Add health check script a3f4b12 docs: Add Day 01 notes
$git revert c8d9e01 # Creates new "undo" commit, preserves history
[main f1e2d3c] Revert "feat: Add health check script" # SAFE: history shows what happened, no data lost
git log — visual branch view
$git log --oneline --graph --all
* c8d9e01 (HEAD -> main, origin/main) feat: Add health check script * a3f4b12 docs: Add Day 01 notes # --graph shows branch lines visually. --all shows all branches.
INT Q →"Walk me through how you'd use git in a team environment."
Model answer: "My workflow starts with pulling the latest main: git pull. Then I create a feature branch named after the work: git checkout -b feature/nginx-config-update. I do the work in small focused commits. If I need to switch context mid-task I stash unfinished work with git stash. When the feature is done, I push the branch to GitHub and open a Pull Request — a PR gives teammates a chance to review the code before it hits main. After the PR is approved and merged, I delete the branch both locally and on the remote. I never commit directly to main — main should always be in a deployable state."

Linux Text Processing — The Commands That Actually Run DevOps

Slot after: grep section
Time: ~60 minutes

Why These Were Missing and Why They Matter Now

The Day 1 pack covered grep and cat but skipped the text processing tools that show up constantly in production: awk (used in the Day 4 health_check.sh script already), cut, sort, uniq, wc, and tar. These are the tools you use every day to parse logs, extract data, and manage files. You've already seen awk in Day 4 — now understand why it works.

⌨️ awk, cut, sort, uniq, wc, tar — Full Command Flow

Text Processing on EC2 — Day 1 Session 2 Add-on Day 1 Add-on
awk — column extraction (you already used this in health_check.sh)
$df -h
Filesystem Size Used Avail Use% Mounted on /dev/xvda1 8G 1.4G 6.6G 18% /
$df -h | awk 'NR==2 {print $5}'
18% # awk: NR==2 = row 2 (skip header). $5 = column 5 (Use%). 100% readable.
$df -h | awk 'NR>1 {print $1, $5}' # NR>1 = all rows except header
/dev/xvda1 18%
$free -m | awk 'NR==2 {print $4}' # RAM free (column 4, row 2)
842
$ps aux | awk '{print $1, $11}' | head -5 # User + Process name
USER COMMAND root /sbin/init
cut — extract fields from delimited text
$cat /etc/passwd | cut -d: -f1
root daemon ubuntu # -d: = delimiter is colon. -f1 = field 1 (username)
$echo "2026-06-05 14:30:01" | cut -d' ' -f1
2026-06-05 # Split on space, take first field (date). Used for log parsing.
$echo "192.168.1.1" | cut -d. -f1-3
192.168.1 # -f1-3 = fields 1 through 3 (first 3 octets of IP)
sort + uniq — count and deduplicate
$cat /var/log/nginx/access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -10
127 203.0.113.45 43 198.51.100.22 12 192.0.2.1 # Top 10 IP addresses hitting your nginx server, sorted by frequency # sort: alphabetically. uniq -c: count consecutive duplicates. sort -rn: reverse numeric sort. # This pipeline is real log analysis — used in incident response daily.
$cat /var/log/auth.log | grep "Failed password" | wc -l
147 # How many failed SSH login attempts today. On a public EC2: this is always non-zero. # This is why you use key-based auth, not passwords.
wc — count lines, words, characters
$wc -l /var/log/syslog
4521 /var/log/syslog
$wc -l /etc/passwd
30 /etc/passwd # 30 user accounts on this server — useful baseline to know
$ls /etc/ | wc -l
196 # Count files/directories in /etc — pipe anything into wc -l
tar — compress and extract archives
$tar -czf backup-$(date +%Y%m%d).tar.gz ~/devops-notes/
# -c = create archive. -z = gzip compress. -f = filename to write to # Result: backup-20260605.tar.gz
$tar -tzf backup-20260605.tar.gz | head -10
# -t = list contents without extracting. Verify before you extract.
$tar -xzf backup-20260605.tar.gz -C /tmp/restore/
# -x = extract. -C = extract TO this directory (must exist)
$aws s3 cp backup-20260605.tar.gz s3://devops-config-YOURNAME/backups/
# Upload backup to S3 — now recoverable from anywhere

journalctl + lsof + scp — Modern Linux Debugging

Slot after: systemctl section
Time: ~30 minutes

The Gap That Will Cost You Most Debug Time

The Day 1 pack used /var/log/nginx/error.log for debugging. That works for nginx specifically. But most modern Ubuntu services write logs to journald, not to files. journalctl is the correct tool for 80% of service debugging on modern Linux. Not knowing it means you're looking in the wrong place.

⌨️ journalctl, lsof, scp

Modern Linux Debugging Commands Day 1 Add-on
journalctl — systemd's centralised log system
$journalctl -u nginx # All logs for nginx service
$journalctl -u nginx -f # -f = follow (live stream like tail -f)
$journalctl -u nginx --since "1 hour ago"
$journalctl -u nginx --since "2026-06-05 14:00" --until "2026-06-05 15:00"
$journalctl -u nginx -n 50 # Last 50 lines only
$journalctl -p err -u nginx # Only error-level messages
# -p levels: emerg, alert, crit, err, warning, notice, info, debug
$journalctl --disk-usage # How much disk journal is using
Archived and active journals take up 56.0M on disk.
$journalctl -b # All logs since last boot
$journalctl -b -1 # Logs from previous boot (useful after a crash)
lsof — what process is using a port
$sudo lsof -i :80
COMMAND PID USER FD TYPE DEVICE SIZE/OFF NODE NAME nginx 2341 root 6u IPv4 18923 0t0 TCP *:http (LISTEN) # If this shows something other than nginx, THAT'S your port conflict
$sudo lsof -i :22 # Who is listening on SSH port
$sudo lsof -p 2341 # All files opened by process ID 2341
$sudo ss -tlnp | grep :80 # Alternative: faster, no lsof needed
LISTEN 0 511 0.0.0.0:80 0.0.0.0:* users:(("nginx",pid=2341,fd=6))
scp — secure copy files to/from EC2
# FROM your laptop TO EC2:
$scp -i ~/.ssh/my-key.pem ~/local-file.txt ubuntu@EC2_IP:~/remote-file.txt
# FROM EC2 TO your laptop:
$scp -i ~/.ssh/my-key.pem ubuntu@EC2_IP:~/logs/health.log ~/Downloads/
# Entire directory:
$scp -ri ~/.ssh/my-key.pem ubuntu@EC2_IP:~/devops-notes/ ~/Desktop/ec2-backup/
# -r = recursive (for directories). Same syntax as cp, but remote. # Use case: download logs for analysis, upload config files to EC2

export, alias, and .bashrc Customisation

Day 1: export + .bashrc
Day 4: alias in scripts

Why These Matter

export is how environment variables are passed to child processes — shell scripts see exported vars, not just local ones. alias saves significant time and every senior engineer uses them. .bashrc is where permanent changes live — without it, your settings disappear on next login.

⌨️ export, alias, .bashrc

Shell Environment — export, alias, .bashrc Day 1 + Day 4 Add-on
export — make variables available to child processes
$MY_VAR="local only"
$bash -c 'echo $MY_VAR'
# Empty — child bash can't see parent's non-exported var
$export MY_VAR="now exported"
$bash -c 'echo $MY_VAR'
now exported # Child process can now see it # This is why AWS_PROFILE, AWS_REGION, PATH must be exported
$export AWS_PROFILE=learning
$export AWS_DEFAULT_REGION=eu-west-1
$export PATH="$PATH:/usr/local/bin" # Add to PATH (colon-separated)
$env | grep AWS # See all exported environment variables matching AWS
AWS_PROFILE=learning AWS_DEFAULT_REGION=eu-west-1
alias — shortcuts for long commands
$alias ll='ls -la'
$ll
total 40 drwxr-xr-x 5 ubuntu ubuntu 4096 Jun 5 14:30 . # alias works for the current session only — lost on next login
$alias # List all current aliases
$unalias ll # Remove alias
# Useful aliases for DevOps work:
$alias gs='git status'
$alias gl='git log --oneline --graph --all'
$alias nlog='sudo tail -f /var/log/nginx/access.log'
$alias myip='curl -s ifconfig.me'
$alias k='kubectl' # Week 8 — preview
.bashrc — make changes permanent across logins
$nano ~/.bashrc
# Add at the bottom of the file:   ## DevOps Learning Customisation export AWS_PROFILE=learning export AWS_DEFAULT_REGION=eu-west-1 export EDITOR=nano   ## Aliases alias ll='ls -la --color=auto' alias gs='git status' alias gl='git log --oneline --graph --all' alias nlog='sudo tail -f /var/log/nginx/access.log' alias myip='curl -s ifconfig.me && echo' alias ports='sudo ss -tlnp'   ## Prompt improvement — show git branch parse_git_branch() { git branch 2>/dev/null | sed -n 's/* //p'; } PS1='\u@\h:\w$([ -n "$(parse_git_branch)" ] && echo " ($(parse_git_branch))")\$ '
$source ~/.bashrc # Apply changes immediately (don't log out)
# Your prompt now shows the current git branch. All aliases persist.

EBS Snapshots — Back Up Before You Break Things

Slot before: Day 3 experiments
Time: 10 minutes

⚠ The habit that saves you from rebuilding

Before any Day 3+ experiment that modifies your EC2 significantly, take a snapshot. A snapshot is an EBS backup — it costs a few cents per GB per month and takes 2 CLI commands. Not taking one before a major config change and then breaking the server costs you 2 hours of rebuilding.

EBS Snapshot — Quick Backup Before Experiments Day 3 Add-on
$INSTANCE_ID=$(curl -s http://169.254.169.254/latest/meta-data/instance-id)
$VOLUME_ID=$(aws ec2 describe-instances \
--instance-ids $INSTANCE_ID \
--query 'Reservations[0].Instances[0].BlockDeviceMappings[0].Ebs.VolumeId' \
--output text)
$echo "Volume to snapshot: $VOLUME_ID"
$aws ec2 create-snapshot \
--volume-id $VOLUME_ID \
--description "Pre-experiment backup $(date +%Y-%m-%d)"
{ "SnapshotId": "snap-0a1234567890abcde", "State": "pending" } # Snapshot runs in background. Takes 5-20 min depending on disk size. # Cost: ~$0.05/GB/month — essentially free for a learning t2.micro (8GB = $0.40/month)
$aws ec2 describe-snapshots --snapshot-ids snap-0a1234567890abcde \
--query 'Snapshots[0].State' --output text
completed # When "completed" — safe to proceed with experiments # To restore: create new volume from snapshot, attach to EC2 # Clean up old snapshots: aws ec2 delete-snapshot --snapshot-id snap-xxxx

⚠ Additional Beginner Mistakes Found in Audit
✗
Working directly on the main branch — no branching workflow

Every commit goes straight to main. This means you can't separate experimental work from stable code. On a team, this blocks everyone when you break something.

✓ Fix: Create a branch for every piece of work: git checkout -b feature/what-you-are-doing. Merge to main only when it works.
✗
Not setting a billing alarm before starting AWS practice

Forgotten NAT Gateways, left-running EC2s in unexpected regions, and accidentally created services have cost learners hundreds of pounds. This is the most financially dangerous beginner gap.

✓ Fix: Set a CloudWatch billing alarm for $10 and an AWS Budget on Day 2 — before any other AWS work. Takes 4 minutes. See Billing Safety section above.
✗
Using /var/log/ when journalctl would find the answer faster

Some services write to both. Many write only to journald. If your Google search says "check /var/log/service.log" and it's empty or doesn't exist — the service is writing to journald. Checking only /var/log/ means you miss half the logs on modern Ubuntu.

✓ Fix: For any service issue, run journalctl -u SERVICE -n 50 first. Then check /var/log/ if journal is empty.
✗
Thinking git reset --hard is the right way to undo a commit on a shared branch

git reset --hard rewrites history. If you've pushed to GitHub and others have pulled, reset creates divergent histories that require a force push — which overwrites colleagues' work. This is a serious team incident.

✓ Fix: Use git revert on any commit that has been pushed. It creates a new "undo" commit, preserves history, and is safe for shared branches.
✗
Not understanding that aws configure sets the DEFAULT profile, not a named one

Running aws configure without --profile sets credentials for the [default] profile. If you later run aws configure --profile learning, you now have two profiles but all commands still use [default] unless you specify --profile learning or set AWS_PROFILE. Confusion leads to commands running in the wrong account.

✓ Fix: Always use named profiles from Day 2: aws configure --profile learning. Set export AWS_PROFILE=learning in .bashrc. Verify with aws sts get-caller-identity before important operations.
Interview Gaps

Interview Prompts — Gap Topics

Practise these out loud
INT Q →"How do you diagnose a service that's failing to start — walk me through your process."
Model answer: "First step is always to check the service status: sudo systemctl status servicename — this shows the last few log lines and the exit code. If the status isn't enough detail, I go to the journal: journalctl -u servicename -n 50 gives me the last 50 log entries for that unit. If it's a port conflict — another process already using port 80 for example — I check with sudo ss -tlnp or lsof -i :80 to see what process has the port. For nginx specifically I also run sudo nginx -t to test config syntax before attempting a restart. I work top-down: service status → logs → config → resources — rather than restarting blindly and hoping."
INT Q →"What is the difference between git revert and git reset?"
Model answer: "Both undo changes but in fundamentally different ways. git revert creates a new commit that reverses the changes from a previous commit — the original commit stays in history. It's safe to use on any branch including shared ones because it doesn't rewrite history. git reset moves the HEAD pointer backwards — it can remove commits from history entirely. reset --hard also discards working directory changes. Reset is useful for cleaning up local commits before a first push, but you should never use it on a branch that teammates have already pulled from because it creates divergent histories that require a force push. My rule: revert on anything that's been pushed, reset only on strictly local work."
INT Q →"How do you make a configuration change permanent on a Linux server vs just the current session?"
Model answer: "It depends on what you're changing. For shell environment variables and aliases — things you want every time you log in — I add them to ~/.bashrc (or ~/.bash_profile for login shells). After editing, I run source ~/.bashrc to apply without logging out. For PATH changes, service configurations, or system-wide settings, it depends on the service: nginx config lives in /etc/nginx/, systemd unit files live in /etc/systemd/system/. For a service change, after editing the unit file I run systemctl daemon-reload and then systemctl restart or reload. The key mental model is: anything done in a terminal session is temporary — to make it survive reboots or new login sessions, it needs to be written to the appropriate config file."

⚡ Week 1 Supplement Quiz — Covers All Gap Topics
Q1. You need to check nginx logs but journalctl -u nginx shows nothing. Where else do you look?
A) /tmp/nginx/
B) /var/log/nginx/error.log and /var/log/nginx/access.log
C) ~/.nginx/logs/
D) /etc/nginx/logs/
nginx writes its own logs to /var/log/nginx/ in addition to (or instead of) journald, depending on configuration. If journalctl is empty, the nginx-specific log files are the next place to check. Access log shows all requests; error log shows failures.
Q2. What does this command do: cat /var/log/auth.log | awk '{print $1,$2}' | sort | uniq -c | sort -rn | head -5
A) Deletes the 5 oldest auth log entries
B) Shows the 5 most frequent date-time combinations in the auth log — a basic log frequency analysis
C) Copies the auth log to a new file
D) Counts total lines in the auth log
This pipeline: extracts columns 1+2 (date and time), sorts them alphabetically, counts consecutive duplicates with uniq -c, sorts numerically in reverse, and shows top 5. The result is: which minute had the most auth log activity — useful for spotting brute-force attack patterns.
Q3. Your .bashrc has alias gs='git status' but after running source ~/.bashrc, the alias stops working when you run a shell script that calls gs. Why?
A) Shell scripts don't support aliases
B) Aliases are only available in interactive shells by default — not in non-interactive script subshells
C) The alias syntax is wrong
D) You need to restart the EC2
Bash only expands aliases in interactive shells by default. A script runs in a non-interactive subshell where .bashrc aliases are not loaded. Solution for scripts: use the full command (git status) or use a function instead of an alias. This is why aliases are for human sessions, not automation scripts.
Q4. You want to securely copy a log file from your EC2 to your laptop. Which command?
A) aws s3 cp only works for this
B) scp -i key.pem ubuntu@EC2_IP:~/logs/health.log ~/Downloads/
C) ssh -i key.pem ubuntu@EC2_IP cat health.log
D) rsync is the only option
scp (secure copy) uses SSH under the hood — same key, same host, same user. The syntax is source → destination. For EC2-to-local: ubuntu@IP:remote/path local/path. It transfers the file directly over your SSH connection without any AWS CLI or S3 required.
Q5. Why must billing alerts be set in us-east-1 specifically, even if your EC2 is in eu-west-1?
A) It's a bug in AWS
B) Billing alarms only work in us-east-1 for paid accounts
C) AWS publishes estimated charge metrics to CloudWatch only in us-east-1 — it's the global billing region regardless of where your resources are
D) You can use any region for billing alarms
AWS billing is a global construct aggregated in us-east-1. The EstimatedCharges CloudWatch metric only exists in us-east-1. If you create a billing alarm in eu-west-1, it simply won't have the metric to trigger on — the alarm will never fire. Always use --region us-east-1 for billing-related CloudWatch operations.
Q6. What does tar -czf archive.tar.gz ~/scripts/ do and what does each flag mean?
A) Extracts archive.tar.gz into ~/scripts/
B) Creates (-c) a gzip-compressed (-z) archive (-f) named archive.tar.gz containing the ~/scripts/ directory
C) Lists the contents of an existing archive
D) Compresses only without creating an archive
-c = create a new archive. -z = compress using gzip (smaller file). -f = the next argument is the filename to write to. To extract: tar -xzf archive.tar.gz. To list without extracting: tar -tzf archive.tar.gz. The "czf" mnemonic: Create Zipped File.
